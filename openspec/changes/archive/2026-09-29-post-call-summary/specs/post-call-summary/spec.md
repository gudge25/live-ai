# Spec Delta

## Purpose

Генерує коротке текстове резюме розмови через AssemblyAI LLM Gateway одразу після завершення дзвінка і доставляє його клієнту окремою подією, щоб оператор бачив суть розмови, не гортаючи всі репліки.

## ADDED Requirements

### Requirement: Summary generation trigger
Коли сесія завершується (hangup), сервіс SHALL, якщо фіча увімкнена конфігурацією, надіслати зібраний фінальний транскрипт обох сторін (у хронологічному порядку, з позначкою сторони, без часових позначок) в AssemblyAI LLM Gateway для отримання короткого резюме. Запит MUST відбуватися асинхронно і MUST NOT затримувати подію `session_ended`.

#### Scenario: Call ends with transcript
- **WHEN** розмова завершується і накопичено хоча б одну фінальну репліку
- **THEN** сервіс надсилає запит на резюме до AssemblyAI LLM Gateway, не чекаючи на відповідь перед публікацією `session_ended`

#### Scenario: Call ends with empty transcript
- **WHEN** розмова завершується без жодної фінальної репліки (наприклад, дзвінок обірвався одразу)
- **THEN** сервіс SHALL NOT надсилати запит на резюме

#### Scenario: Feature disabled
- **WHEN** генерація резюме вимкнена конфігурацією
- **THEN** сервіс не надсилає запит на резюме і поведінка решти завершення сесії не змінюється

### Requirement: LLM Gateway request
Запит на резюме SHALL іти на `POST https://llm-gateway.assemblyai.com/v1/chat/completions` з тим самим `ASSEMBLYAI_API_KEY`, що вже використовується для realtime-стрімінгу, з текстом транскрипту безпосередньо в тілі повідомлення (без `transcript_id`, оскільки транскрипт не є об'єктом асинхронного AssemblyAI API). Модель MUST бути конфігурованою, з дефолтним значенням.

#### Scenario: Successful response
- **WHEN** AssemblyAI LLM Gateway повертає 200 з текстом резюме
- **THEN** сервіс використовує цей текст як резюме розмови

#### Scenario: Request timeout
- **WHEN** запит до LLM Gateway не завершується протягом розумного таймауту
- **THEN** сервіс скасовує запит і трактує це як відсутність резюме для цієї розмови (без повторних спроб)

### Requirement: Summary delivery event
Бекенд SHALL доставляти готове резюме клієнтам UI окремою подією WebSocket-протоколу, прив'язаною до `sessionId` вже завершеної сесії, а не як частину `session_ended`. Подія MUST надсилатися лише вже підключеним клієнтам та новим клієнтам, що підключаються, доки сесія ще присутня в історії (`UI_HISTORY_LIMIT`).

#### Scenario: Summary ready after session ended
- **WHEN** резюме отримано вже після того, як клієнт побачив `session_ended` для цієї сесії
- **THEN** клієнт отримує окрему подію з резюме і прив'язує її до тієї самої розмови за `sessionId`

#### Scenario: New client connects while summary still pending
- **WHEN** новий клієнт підключається до того, як резюме для нещодавно завершеної сесії з історії ще не готове
- **THEN** клієнт отримує снапшот історії без резюме для цієї сесії, а резюме приходить окремою подією, коли буде готове

#### Scenario: New client connects after summary already ready
- **WHEN** новий клієнт підключається після того, як резюме для сесії з історії вже було отримано
- **THEN** снапшот історії для цієї сесії вже містить резюме, без потреби чекати на окрему подію

### Requirement: Failure isolation
Якщо запит до LLM Gateway провалюється (помилка мережі, не-2xx відповідь, таймаут), сервіс SHALL продовжити нормальну роботу без резюме для цієї розмови і MUST NOT надсилати клієнту подію помилки, що блокує UI.

#### Scenario: LLM Gateway returns error
- **WHEN** AssemblyAI LLM Gateway повертає не-2xx статус
- **THEN** сервіс логує помилку на рівні `warn`, не публікує подію резюме для цієї сесії, і решта функціоналу (транскрипція, нові дзвінки) не порушується

### Requirement: Summary display in extension
Chrome-розширення SHALL показувати отримане резюме у картці відповідного завершеного дзвінка в історії. Якщо резюме відсутнє (вимкнено, порожній транскрипт або помилка), картка SHALL відображатися так само, як і зараз, без резюме.

#### Scenario: Summary arrives for a call in history
- **WHEN** розширення показує картку завершеного дзвінка і надходить подія резюме для цього `sessionId`
- **THEN** картка оновлюється й показує текст резюме без перезавантаження історії

#### Scenario: Call scrolled out of history before summary arrives
- **WHEN** резюме приходить для сесії, яку вже витіснено з `UI_HISTORY_LIMIT`
- **THEN** розширення ігнорує подію без помилки
